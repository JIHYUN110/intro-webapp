# 13주차 진행 가이드 — MVP 구현 및 디버깅 (DynamoDB + AppSync)

```
브라우저 ─HTTPS─▶ CloudFront ─OAC─▶ S3 (12주차 완료)
브라우저 ─GraphQL(API 키)─▶ AppSync ─IAM 역할─▶ DynamoDB (Question / Score / Guestbook)
```

> 🌏 **이번 주 작업은 전부 서울(ap-northeast-2) 리전**에서. 콘솔 오른쪽 위 리전을 먼저 바꾸세요.
> (IAM 정책 JSON이 서울 리전·계정 243112136765 기준으로 작성돼 있어요.)
> 📸 = 제출/디버깅 이력서용 캡처 지점. 오류가 나면 **바로 캡처** 해두세요.

## 1단계. DynamoDB 테이블 3개 만들기 (약 10분)

DynamoDB → 왼쪽 **테이블** → **테이블 생성**. 3번 반복합니다.

| 테이블 이름 | 파티션 키 | 정렬 키 |
|---|---|---|
| `Question` | `id` (문자열) | (비움) |
| `Score` | `board` (문자열) | `sk` (문자열) |
| `Guestbook` | `board` (문자열) | `sk` (문자열) |

- 테이블 설정: **설정 사용자 지정** → 읽기/쓰기 용량 설정: **온디맨드** (나머지 기본값)
  - "기본 설정"으로 두면 프로비저닝 모드가 될 수 있어요. 사용하지 않아도 요금이 나가는 걸 막으려면 온디맨드를 선택하세요.
- 대소문자 정확히! (`Score` ≠ `score`)

**키 설계 이유 (디버깅 이력서·보고서에 그대로 써도 됨)**
- `board`: 모든 글이 같은 값(`RANK` / `GUESTBOOK`)을 가져서 **Query 한 번으로 전체 조회**
- `sk` = `등록시각#id`: 시간순으로 자동 정렬되고, 같은 시각에 2명이 등록해도 키가 겹치지 않음
- 방명록은 `sk` **내림차순 Query + limit 20** → 기획서의 "최신순 20개"를 DB에서 바로 처리

📸 **캡처 A**: 테이블 목록 (3개 모두 "활성")
📸 **캡처 B**: Guestbook 테이블 → 개요 → 파티션 키 `board` / 정렬 키 `sk` 보이는 부분

### 1-1. 퀴즈 문제 10개 넣기 (CloudShell)
1. 콘솔 왼쪽 아래 **CloudShell** 클릭 (서울 리전인지 확인)

5. DynamoDB → **항목 탐색** → `Question` → 10개 확인 📸 **캡처 C**

## 2단계. IAM 서비스 역할 (최소 권한) 만들기 (약 5분)

1. IAM → **역할** → **역할 생성**
2. 신뢰할 수 있는 엔터티: **AWS 서비스** → 서비스: **AppSync** 선택 → 다음
3. 권한 추가 화면: **아무것도 체크하지 않고** 다음 (AWS 관리형 `AmazonDynamoDBFullAccess` 같은 정책을 붙이면 최소 권한이 아니에요)
4. 역할 이름: `AppSyncIntroWebappRole` → 역할 생성
5. 만든 역할 클릭 → **권한 추가 → 인라인 정책 생성** → **JSON** 탭
   → `appsync/iam-policy.json` 내용 붙여넣기 → 다음 → 정책 이름 `IntroWebappDynamoDBMinimal` → 정책 생성

| 테이블 | 허용 동작 | 쓰는 곳 |
|---|---|---|
| Question | `Scan` | listQuestions |
| Score | `PutItem`, `Query` | createScore, listScores |
| Guestbook | `PutItem`, `Query` | createGuestbook, listGuestbooks |

→ 삭제(`DeleteItem`), 수정(`UpdateItem`), 다른 테이블 접근은 **불가**.

📸 **캡처 D**: 역할 → 신뢰 관계 탭 (`appsync.amazonaws.com`)

## 5단계. AppSync 콘솔에서 저장·조회 테스트 (약 5분)

왼쪽 **쿼리** → 인증: API 키 선택 → 아래를 하나씩 붙여넣고 ▶ 실행

```graphql
mutation {
  createGuestbook(input: { nickname: "테스트", message: "AppSync 연결 테스트", sticker: "👍" }) {
    id nickname message sticker createdAt
  }
}
```
```graphql
query {
  listGuestbooks(limit: 20) { items { id nickname message sticker createdAt } }
}
```
```graphql
query {
  listQuestions { items { id text choices answer } }
}
```
```graphql
mutation {
  createScore(input: { nickname: "테스트", score: 7, title: "💖 찐친 인증" }) { id nickname score createdAt }
}
```
```graphql
query { listScores { items { nickname score title createdAt } } }
```

## 자주 나는 오류 (디버깅 이력서 참고용)

| 증상 / 메시지 | 원인 | 해결 |
|---|---|---|
| `UnauthorizedException` / `You are not authorized` | API 키 오타·만료, 헤더 누락 | 설정 → API 키 확인·만료일 연장, `api.js` 값 확인 |
| `AccessDeniedException ... not authorized to perform: dynamodb:Query` | IAM 정책에 동작 누락 / 테이블 이름·리전 불일치 | 인라인 정책 Action·Resource ARN 확인 |
| `Cannot return null for non-nullable type` | 리졸버 미연결, 또는 응답 필드 이름이 스키마와 다름 | 리졸버 패널에서 연결 확인, 필드명 대조 |
| `ValidationException: One of the required keys was not given a value` | 테이블 키 이름 불일치 (`board`/`sk` 대소문자) | 테이블 키 이름과 리졸버 key 일치시키기 |
| `Requested resource not found` | 데이터 소스가 다른 리전 테이블을 가리킴 | 데이터 소스 리전 = 테이블 리전(서울) |
| 사이트는 여전히 예전처럼 동작 (로컬 모드) | CloudFront 캐시 / 브라우저 캐시 | 무효화 `/*` + Ctrl+F5 |
| 브라우저 콘솔 `Failed to fetch` | URL 오타 (`/graphql` 누락 등) | 설정의 API URL 그대로 복사 |
| 퀴즈 문제가 안 나옴 (`items: []`) | Question 테이블이 비어 있음 / 다른 리전에 넣음 | CloudShell 리전 확인 후 다시 batch-write |
