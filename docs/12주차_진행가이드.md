# 12주차 과제 진행 가이드 — AWS 환경구성 및 개발환경 구축

기획서 기준 아키텍처: **사용자 → CloudFront(HTTPS) → S3(퍼블릭 차단, OAC)** / (이후 주차) AppSync → DynamoDB

> 📸 = 제출용 캡처 지점. 모든 AWS 작업은 리전 **아시아 태평양(서울) ap-northeast-2** 에서 진행하세요.

---

## 0. 사전 준비
- [ ] 쓰지 않는 RDS(서울·스톡홀름) 삭제 완료 — 크레딧 보호
- [ ] `js/content.js` 의 이름·취향 카드·퀴즈 10문제를 본인 정보로 수정

## 1. 개발환경 구성 (Claude Code — GitHub — AWS)
1. GitHub 로그인 → 오른쪽 위 **+ → New repository**
   - 이름: `intro-webapp` (예시), Public, README 추가 **안 함** → Create
2. 이 폴더에서 push (PowerShell):
   ```powershell
   git remote add origin https://github.com/<GitHub아이디>/intro-webapp.git
   git push -u origin main
   ```
   처음이면 브라우저 로그인 창이 뜨니 로그인하세요.
3. 📸 **캡처 1 – 개발환경 연동 화면**: 한 화면(또는 나란히)에
   - Claude Code 창(이 대화 + 파일 목록)
   - GitHub 저장소 페이지(파일과 커밋이 보이게)
   - AWS 콘솔(오른쪽 위 계정명 보이게)

## 2. S3 버킷 생성 + 업로드
1. 콘솔 검색 **S3 → 버킷 만들기**
   - 버킷 유형: 범용 / 이름: `intro-webapp-2025076299` (전 세계에서 유일해야 함)
   - **객체 소유권: ACL 비활성화됨(권장)**
   - **이 버킷의 퍼블릭 액세스 차단 설정 → "모든 퍼블릭 액세스 차단" ✅ 유지**
   - 나머지 기본값 → 버킷 만들기
2. 버킷 클릭 → **업로드 → 파일 추가 / 폴더 추가**
   - `index.html`, `css/`, `js/`, `assets/` 를 올리기 (`docs/`, `README.md` 는 안 올려도 됨)
   - 업로드 후 버킷 최상위에 `index.html` 이 바로 보여야 해요 (`intro-webapp/index.html` 처럼 한 단계 들어가 있으면 안 됨)
3. ⚠️ **속성 탭의 "정적 웹 사이트 호스팅"은 켜지 마세요.** (OAC는 REST 엔드포인트에서만 동작)
4. 📸 **캡처 2 – 퍼블릭 액세스 차단**: 버킷 → **권한** 탭 → "퍼블릭 액세스 차단: 모두 활성" 부분

## 3. CloudFront 배포 + OAC
1. 콘솔 검색 **CloudFront → 배포 생성**
   - (요금제 선택 화면이 나오면 **Free 플랜** 또는 종량제 선택)
   - **원본 도메인**: 목록에서 `intro-webapp-2025076299.s3.ap-northeast-2.amazonaws.com` 선택
     (❌ `s3-website` 가 들어간 주소는 고르지 마세요)
   - **원본 액세스**: **원본 액세스 제어 설정(권장)** 선택 → **제어 설정 생성** → 기본값 그대로 생성
   - 뷰어 프로토콜 정책: **Redirect HTTP to HTTPS**
   - WAF: 보안 보호 비활성화 (비용 방지)
   - **기본값 루트 객체: `index.html`**
   - 배포 생성
2. 생성 직후 위쪽 노란 배너의 **정책 복사** 클릭 → **S3 버킷 권한으로 이동**
   → 버킷 **권한 → 버킷 정책 → 편집** → 붙여넣기 → 변경 사항 저장
   (구조는 `docs/bucket-policy.json` 참고)
3. 배포 상태가 **배포 중 → 활성(마지막 수정: 날짜)** 될 때까지 3~10분 대기
4. 📸 **캡처 3 – OAC**: CloudFront 배포 → **원본** 탭 → 원본 선택·편집 화면에서 "원본 액세스 제어" 값이 보이게
   (또는 왼쪽 메뉴 **보안 → 원본 액세스** 의 OAC 목록)
5. 📸 **캡처 4 – 버킷 정책**: S3 버킷 → **권한** 탭 → 버킷 정책(`cloudfront.amazonaws.com`, `AWS:SourceArn` 보이게)

## 4. 접속 확인
1. CloudFront 배포의 **배포 도메인 이름** 복사 → `https://dxxxxxxxx.cloudfront.net`
   📸 **캡처 5 – 접속 성공**: 브라우저 주소창 + 자기소개 사이트 화면
2. S3 직접 주소: 버킷 → `index.html` 클릭 → **객체 URL** 복사
   (`https://intro-webapp-2025076299.s3.ap-northeast-2.amazonaws.com/index.html`)
   📸 **캡처 6 – 접속 거부**: `AccessDenied` XML 화면 + 주소창

| OAC | 캡처 3 |
| 버킷 정책 | 캡처 4 |
| (권장) 접속 성공 / S3 직접 접속 거부 | 캡처 5, 6 |

## 6. 파일 수정 후 다시 배포할 때
1. 수정 → `git commit` → `git push`
2. S3에 바뀐 파일 다시 업로드(덮어쓰기)
3. CloudFront → 배포 → **무효화** → 객체 경로 `/*` → 생성 (캐시 갱신, 월 1,000건까지 무료)

## 문제 해결
| 증상 | 원인 / 해결 |
|---|---|
| CloudFront 주소도 AccessDenied | 버킷 정책 미적용, 또는 루트 객체 `index.html` 미설정, 또는 파일이 폴더 안에 업로드됨 |
| CSS·JS가 안 먹고 글자만 나옴 | `css/`, `js/` 폴더 구조 그대로 업로드했는지 확인 |
| 수정했는데 그대로 | CloudFront 무효화 `/*` |
